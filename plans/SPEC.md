# 8b-is-debris — build brief (shared contract)

Both lanes read this. Do not edit this file; ask the orchestrator if the contract is wrong.

## What debris is

A configuration service for a family's streaming setup. It does not host or serve
media. It holds three things:

1. **A configuration broker.** The family has one Real-Debrid / TorBox / StremThru
   account. debris hands short-lived, per-device configuration bundles to Stremio
   clients, so the setup is edited in one place. *As built, the credential itself is
   not stored server-side yet* — the broker exists and serves bundles, and the
   credential store is the one piece still ahead of the code.
2. **A curated addon manifest.** Which addons are allowed (Torrentio, Comet,
   MediaFusion, Jackettio, OpenSubtitles v3), which filters are forced
   (`[8B+]` / `[RD+]` cached-only, so no P2P traffic ever reaches a family device),
   and which catalogues are pinned.
3. **An entitlement ledger.** Who in the family has paid, what tier they are on,
   and how many device seats they may attach.

Explicitly **not** built here: the proxy data path itself, any media bytes, any
P2P, any scraper. The proxy is a documented seam, not shipped code.

## Tiers (EUR, integer minor units — never floats)

| id | name | cents/mo | seats | notes |
|---|---|---|---|---|
| `free` | Free | 0 | 1 | community addons, no cache broker, no subtitles |
| `family` | Family | 490 | 5 | cache broker, HU+EN subtitles, 1080p cap |
| `household` | Household | 990 | 12 | everything in family, 4K HDR, sovereign YouTube layer |
| `patron` | Patron | 1900 | 24 | household + priority relay + 2 guest passes |

## Server contract (lane B owns `server/`)

Plain Node (`node:http`), zero runtime dependencies. Node 26 runs `.ts` directly
(type stripping), so source is `server/src/*.ts`. Tests use `node:test`.

```
GET  /healthz                      -> 200 {ok:true, version, uptime_s}
GET  /api/plans                    -> 200 {plans:[{id,name,cents,seats,features[]}]}
GET  /api/bundle?email=            -> 200 {tier,seats,addons,subtitle_languages,forced_filters,expires_at}
                                     no such email     -> 404 {error:"unknown_entitlement"}
                                     free or past due  -> 402 {error:"payment_required"}
POST /api/checkout                 {plan, email}  -> 200 {url, session_id}
                                     plan unknown      -> 400 {error:"unknown_plan"}
                                     email missing     -> 400 {error:"email_required"}
POST /api/webhook                  raw body + Stripe-Signature header
                                     bad signature     -> 400 {error:"bad_signature"}
                                     otherwise         -> 200 {received:true}
GET  /api/entitlement?email=       -> 200 {email, plan, seats, status, valid_until|null}
                                     unknown email     -> 404 {error:"unknown_entitlement"}
```

Rules:

- **Money is integer cents.** No float ever touches a price.
- **Stripe is reached through one injectable seam** (`createCheckoutSession`,
  passed in as a dependency) so the whole suite runs with no live key and no
  network. The real implementation uses `fetch` against `api.stripe.com` with
  `STRIPE_SECRET_KEY` from env; if the env var is absent the seam is a stub that
  returns a deterministic fake URL and the server logs `stripe: unconfigured`.
- **Webhook signature verification is real code**: HMAC-SHA256 over
  `${timestamp}.${rawBody}` with the endpoint secret, compared in constant time
  against the `v1` candidate in `Stripe-Signature`. Timing-safe compare, no `===`
  on secrets. `STRIPE_WEBHOOK_SECRET` unset → reject every webhook with
  `400 bad_signature` (fail closed, never fail open).
- **The bundle never carries the credential.** `createBundle` has no token field, and
  a test asserts the serialised bundle contains no `token`, `credential`, `secret`,
  `api_key`, or `password`.
- **Entitlements persist to `server/data/entitlements.json`**, written atomically
  (tmp file + rename). The directory is created on demand. No database.
- Handle `checkout.session.completed` (grant plan, set `valid_until` one month
  out from `created` × 1000), `customer.subscription.updated`,
  `customer.subscription.deleted` (downgrade to `free`), and
  `invoice.payment_failed` (mark `past_due`).
- Unknown event types are acknowledged with `200 {received:true, ignored:true}`.

## Landing (lane A owns `landing/`)

Static, no build step: `index.html`, `tokens.css`, `app.js`. Self-hostable from
any file server or object store. Wears the 8b.is constellation ink — read
`../8b-is/design/DESIGN.md` and copy the token values into `landing/tokens.css`
as CSS custom properties (do not `@import` across repos; the landing must be
standalone).

Sections: mark + one-line positioning, the three-tier comparison (free / family /
household, patron as a quiet footnote row), how it works in 3 steps, a "what
debris never does" block (no media hosting, no P2P, no tracking, no ads), and a
footer that states the price hedge ("billed monthly, cancel any time").

Copy rules from DESIGN.md §7: lowercase kickers, sentence-case prose, no
exclamation marks in body copy, numbers always carry their hedge. One solid
`--mint` primary button per tier. Every tier CTA posts to `/api/checkout` with
`{plan, email}` from a single email field at the top of the pricing block, and
renders the returned `url` as a link. Handle the 400s by rendering the returned
`error` string verbatim.

## Definition of done

- Lane A: `landing/` renders with no console errors, keyboard reachable, honours
  `prefers-reduced-motion`, no external network requests.
- Lane B: `node --test server/test/` green, including bad-signature, unknown-plan,
  and atomic-write cases.

## As built (2026-11-12)

This brief is kept as the contract both lanes implemented against, not as a
description of the current tree. Where the build had to deviate, it is recorded
here rather than left to be discovered as a contradiction.

- **Landing is four files, not three.** `landing.css` was added for the layout and
  components, so `tokens.css` stays purely the palette. `index.html` links both.
- **`app.js` is a classic deferred script, not an ES module.** A `type="module"`
  script is blocked over `file://`, which would break the "open it off the
  filesystem" promise. This was a real defect caught in the browser, not a style
  preference.
- **Plan is validated before email**, so a request with neither returns
  `unknown_plan`, not `email_required`. Both are 400s; the order is pinned by a test.
- **`server/src/consts.ts` was added** for the body cap, default port, webhook
  tolerance, ledger file mode, and version.
- **The webhook also returns `bad_payload`** for a correctly signed but unparseable
  body. It is not in the table above; it is in `webhook.ts` and tested.
- **Price ids come from `STRIPE_PRICE_<TIER>`** in the environment, defaulting to a
  clearly invalid `price_unconfigured_<tier>`. The amount lives in Stripe, where the
  invoice is produced, so a placeholder surfaces as a Stripe error rather than a
  silently wrong charge.
- **Entitlements persist to a JSON ledger with atomic tmp+rename writes** and a
  single-flight queue, so concurrent writes cannot interleave.
- **`oneMonthAfter` clamps to the last valid day.** A naive month addition turns
  31 January into 3 March. Clamping is what a subscription means.
